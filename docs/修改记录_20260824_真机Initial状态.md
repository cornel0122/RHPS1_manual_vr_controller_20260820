# 2026-08-24 真机 Initial 状态修复

## 现象

RHPS1 已按标准硬件流程执行 `Go half sitting`、`Remove force sensor offset` 和
`Calib inertia sensor`，随后启动 `ANAAvatarControllerRHPS1_manual`。但是 FSM 一直
停在 `LIPMWalking::Initial`，`next_state_ready=false`，GUI 也不出现 walking
controller 的 `Start standing` 按钮，因此 Vive bridge 从未启动。

## 原因

manual controller 直接使用了 `LIPMWalking::Initial` 的默认行为。该状态会再次把
posture task 设为 controller 内部的 half-sitting 目标，并等待任务速度收敛。真机已经
由 RHPS1 硬件流程进入可控姿态，不应在切换 controller 后重复执行这一姿态重置。

## 修改

新增 `ANA::ManualInitial`：

```yaml
ANA::ManualInitial:
  base: LIPMWalking::Initial
  autoplay: true
  resetPosture: false
```

`ANAAvatarControllerRHPS1_manual` 的顶层初始状态由 `LIPMWalking::Initial` 改为
`ANA::ManualInitial`。该状态保留当前机器人姿态并自动输出 `Standing`，随后进入
`ANA::ManualDemo`。普通 RHPS1 controller、共享自主配置、Vive 标定矩阵和输入映射
均未修改。

## 安全边界

该修改依赖操作者在 Start MC Control 前完成 RHPS1 标准 half-sitting 和传感器校准
流程。首次验证仍需保持 Vive 启动门控：进入 `Avatar::Retargetting::Manual` 后，
机器人在左右 `menu` 均确认前必须保持当前手臂姿态。
