# RHPS1 真机启动清单（当前版，2026-11-18）

整合自：AIST Hands-on 教程（`实体机器人的教程/02.pdf`，Thomas Duvinage）、
`RHPS1当前工作完整交接_20261118.md`、`RHPS1_IOB与手部模型切换_20261106.md`、
`Cornel_Vive单侧轻装测试_20261105.md`，以及 8 月的部署说明和现场命令。

> 本清单只是汇总，执行时以现场工程师和机器人上的实际脚本为准。

## 0. 安全前提（每次都要满足）

- 不单人测试，测试前需获得负责人批准。
- 穿安全鞋，机器人周围无人。
- 急停有人值守。controller 的 menu 暂停**不能代替急停**。
- 机器人运动时不重装 controller、不切换模型、不重启 ROS daemon、不改串口配置。

## 1. 上电（教程 p.11）

RHPS1 使用外部电源：

1. 确认外部电源线已连接到机器人。
2. 打开主电源开关（在机器人腰部前方）。
3. 打开 Control computer（同在腰部前方）和 Vision computer（背部，橙色按钮）。

`RHPS1init` 会在开机时自动运行，建立 IOB 共享内存。如果开机后太早 SSH 登录，可能会遇到共享内存未建立的情况，此时 `bodystat` 无法启动，需要手动运行：

```bash
/home/rhps1user/workspace/install/bin/RHPS1init
```

> 这条命令会影响实体机器人状态，只能按现场流程执行。

## 2. 只在更换手部硬件后：核对模型一致性

Sake2 和 LEAP 之间切换时，下面 8 项必须全部一致，详见 `RHPS1_IOB与手部模型切换_20261106.md`：

| # | 位置 | LEAP | Sake2 |
|---|---|---|---|
| 1 | Control PC IOB 分支 | `topic/leap_hand` | 对应分支 |
| 2 | `~/workspace/src/hrpcnoid_rhps1/CMakeLists.txt` `RHPS1_MODEL_NAME` | `RHPS1main_leap_leap` | `RHPS1main_sake2_sake2` |
| 3 | Control PC `~/workspace/src/openhrp/RHPS1/model/RHPS1.yaml` `modelFile` | `RHPS1main_leap_leap.wrl` | `RHPS1main_sake2_sake2.wrl` |
| 4 | Terminal PC 上的同一个 `RHPS1.yaml` | 同上 | 同上 |
| 5 | `standardPose` 的手部零值 | 32 个 | 无 |
| 6 | `~/.config/mc_rtc/mc_rtc.yaml` | `MainRobot: RHPS1_leap_leap`<br>`Enabled: ANAAvatarControllerRHPS1CornelVive_leap_manual` | `MainRobot: RHPS1_sake2_sake2`<br>`Enabled: ANAAvatarControllerRHPS1CornelVive_manual` |
| 7 | `install/bin/RHPS1init` 中 `alloc_iob` 的模型 | 与上面一致 | 与上面一致 |
| 8 | `~/.config/mc_rtc/plugins/LEAPHandPlugin.yaml` 左右串口 | 按实际安装的手启用 | — |

只读核对命令（在 Control PC 执行）：

```bash
grep -nE '^[[:space:]]*(MainRobot|Enabled):' ~/.config/mc_rtc/mc_rtc.yaml
grep -nE '^[[:space:]]*alloc_iob' ~/workspace/install/bin/RHPS1init
grep -n 'RHPS1_MODEL_NAME' ~/workspace/src/hrpcnoid_rhps1/CMakeLists.txt
grep -nE '^[[:space:]]*modelFile:' ~/workspace/src/openhrp/RHPS1/model/RHPS1.yaml
sed -n '1,120p' ~/.config/mc_rtc/plugins/LEAPHandPlugin.yaml
```

在 Terminal PC 执行：

```bash
grep -nE '^[[:space:]]*modelFile:' ~/workspace/src/openhrp/RHPS1/model/RHPS1.yaml
```

常见报错及含义：

- `bodystat` 报 `iob memory size mismatch`：模型、安装的库和共享内存的自由度不一致。必须停止，重新按流程初始化。
- `got 74 encoder values but 42 values are expected`：`MainRobot` 与实际硬件不匹配。

## 3. Operator PC（本机）：启动 VIVE

1. 启动 SteamVR，等所需设备全部稳定变绿：
   - `right` 模式：waist tracker、右 arm tracker、右 controller。
   - `both` 模式：再加 HMD、左 arm tracker、左 controller。
2. 启动 talker（脚本会自动设置 ROS 环境：domain 200 + Zenoh）：

   ```bash
   cd ~/luyisi/rhps1_cornel_vive_controller/operator_pc
   ./run_vive_talker_rhps1 --control-mode right   # 或 left / both
   ```

如果在本机另开终端检查 topic，需要先 `source operator_pc/rhps1_ros_env.sh`，否则看不到 topic。

> **2026-11-24 起 Operator PC 的 Zenoh 默认用 client 模式**（`config/rhps1_operator_zenoh_client.json5`，
> 所有数据经 Control PC 上的路由器 `.199:7447` 中转）。原来的 peer 配置当天完全收不到 VIVE 数据：
> Control PC 上的进程只监听 127.0.0.1，从不连回 Operator PC。现象是 RViz `Avatar / Vive` 里
> `Right data` / `Left data` 全为 false、`Active side` 停在 `both`。
> 另外：**本机网络断开重连后要重启 talker**（talker 启动时网络未连上会导致对外信息不完整）。

## 4. Control PC：确认收到 VIVE 数据（还没启动机器人控制）

```bash
source /opt/ros/humble/setup.bash
export AMENT_PREFIX_PATH=/home/rhps1user/workspace/install:$AMENT_PREFIX_PATH
export PYTHONPATH=/home/rhps1user/workspace/install/local/lib/python3.10/dist-packages:$PYTHONPATH
export LD_LIBRARY_PATH=/home/rhps1user/workspace/install/lib:$LD_LIBRARY_PATH
export ROS_DOMAIN_ID=200
export RMW_IMPLEMENTATION=rmw_zenoh_cpp
export ROS_LOCALHOST_ONLY=0
unset ZENOH_SESSION_CONFIG_URI

ros2 interface show vr_interface_msgs/msg/Controller
timeout 8 ros2 topic echo /ana/vive_control_mode std_msgs/msg/String --once
```

**收不到数据就不要往下走。**排查顺序：talker 是否在运行 → Zenoh router `:7447` 是否可达 → 环境变量 → 路由。不要先去改 controller。

Zenoh 打印的 scouting warning 本身不代表通信失败，以实际能否收到数据为准。

## 5. Terminal PC：标准启动窗口（教程 p.17）

| 窗口 | 命令 | 用途 |
|---|---|---|
| 1 | `C`（SSH 到 Control PC）→ `bodystat` | 监视机器人状态 |
| 2 | SSH 到 Control PC → `tail -f /var/log/io-main.log` | 监视硬件日志 |
| 3 | `C` → `rhps1` → `sudo -E ./hrpsys_mc_rtc.sh` | 启动 hrpsys + mc_rtc。终端里要有与第 4 步相同的 ROS 环境 |
| 4 | `rhps1` → `./nocnoid22.py` | 机器人操作 GUI（教程里叫 `nocnoid.py`，现场实际用 `nocnoid22.py`） |
| 5 | `ros2 launch mc_rtc_ticker display.launch` | mc_rtc GUI / RViz |

窗口 3 要用 `sudo -E`，否则 ROS 环境不会保留，controller 会报 `vr_interface_msgs ... invalid`。

## 7. Start MC Control 之前逐项确认

1. `bodystat` 正常，脚底接触正常，机器人站稳。
2. 急停人员已就位。
3. 第 2 节的模型与 controller 名称一致。
4. mc_rtc 日志里没有 missing state、missing symbol、message type、joint limit 或 collision 错误。
5. Vive bridge 已加载并完成订阅。
6. waist tracker 已固定牢靠，不会在绑带上转动。
7. 操作者自然站立，controller 保持不动。

Start 之后，FSM 应依次进入 `ANA::ManualInitial` → `Standing` → `ANA::ManualDemo`。

## 8. 开始遥操作

先在 GUI 的 `Avatar / Vive` 页确认：`Active side` 正确，所选一侧的 controller、arm tracker 和 waist tracker 都是 true。

| 按键 | 作用 |
|---|---|
| menu 短按 | 开始或继续控制（`both` 模式要左右同时按，单侧模式按那一侧） |
| menu 长按 1.5 s | 暂停并保持当前目标 |
| 后部 trigger | 连续控制夹具开合（Sake2）或整手开合（LEAP） |
| grip | 只发送“已抓住物体”通知，不改变手指目标 |

> 8 月的旧文档里 grip 和 trigger 的作用是反过来的，以本表为准。
>
> **LEAP 的 trigger 方向（2026-11-24 起）**：旧版是“松开 = 握拳、按下 = 张开”；新版对 `_leap_` 变体交换了两端，
> 改为**松开 = 张开、按下 = 握拳**（内置 A/B/C/D 的闭合方向随之一致）。手指关节的真实对应关系仍有误
>（根部侧摆/弯曲对调、方向相反，见 `docs/LEAP关节方向核对_测试步骤.md` 与交接文档），只影响按关节角
> 精确指定的姿态（ring、RViz 编辑器），不影响整手开合。首次使用：按 menu 开始后手会张开，先空手慢慢扣 trigger 确认。

首次动作测试的顺序：

1. Start 之后先不按 menu，轻轻移动 controller，机器人应该**不跟随**。
2. 按 menu，等待 handover 完成。
3. 每次只测一个方向，每次 2–3 cm：上下 → 前后 → 左右 → 小角度旋转 → arm tracker → HMD 头部（仅 `both` 模式）。
4. 手臂静止时才单独测试夹具或手指。

出现以下情况时，由现场负责人立即停止 MC Control：突然跳变、肩部连续旋转、手臂被拉向远处、机身明显摇晃、关节接近限位、脚底异常。之后保存 `io-main.log` 和 mc_rtc 日志。

### 8.1 输入安全层（`c043063` + `3574d42` 起）首次上真机核对

这两个提交只在 MuJoCo（假 VIVE 剧本）中验证过，第一次在真机上运行时逐项确认：

| 行为 | 旧版本 | 新版本，应观察到 |
|---|---|---|
| 按 menu 开始/继续 | 立即跟随（可能猛冲向操作者手位） | 约 1 s 平滑过渡后跟随 |
| 长按 menu 暂停 | 手被拉回 controller 启动时的姿态 | **手停在暂停时的位置不动** |
| 手柄被遮挡（丢失追踪） | menu 失效，无法暂停 | 手保持不动，长按 menu 仍可暂停 |
| 1.5 s 延迟条件下暂停 | 约 3 s 才生效 | 1.5 s 生效（menu 不随输入延迟） |
| VIVE 数据中断 > 0.25 s | 保持最后目标，速度前馈可能残留 | 冻结目标并清零速度前馈，GUI 显示 `STALE` |
| VIVE 位姿跳变 | 目标瞬间跳过去 | 目标以 ≤ 1.5 m/s、4 rad/s 平滑移动 |

GUI `Avatar / Vive` 新增两行：
- `Input stale (L hand / R hand / L arm / R arm / waist)`：正常应全部为 `ok`。
- `Speed-limited cycles`：正常操作时应基本不增长。若普通动作中持续增长，说明 1.5 m/s 限速影响了手感，可在 `controller/etc/robots/rhps1.yaml` 调高 `target_max_linear_speed` / `target_max_angular_speed`。

建议首次测试顺序：开始（看 1 s 过渡）→ 小幅移动 → 长按暂停（确认手不回弹）→ 继续 → 用手遮挡手柄 1–2 s（确认手不动）。

**手部 / 大臂跟随刚度（新版起 50，旧版实际一直是 5）**：跟随会明显变“紧”——手更快跟上、更接近操作者手位
（MuJoCo：静止误差 21 cm → 2 cm，滞后 256 → 100 ms）。首次使用先小幅慢动作确认；手感太硬或抖动时，
在 RViz `Avatar / Vive` 的 `Hand task stiffness` / `Arm task stiffness` 实时调低（如 30），<= 0 恢复旧行为。

### 8.2 实验模式：controller 只启动一次，在 Operator PC 切换条件（尚未上真机）

使用 `*_experiment` 变体（LEAP：`Enabled: ANAAvatarControllerRHPS1CornelVive_leap_experiment`，其余与 LEAP 手动版相同）。
条件 1（无延迟、无辅助）的行为等同纯手动版，因此实验日可以全程只用这一个 controller。

Operator PC 开两个终端，二者全程不需要重启：

```bash
# 终端 1：VIVE talker（与条件无关）
./run_vive_talker_rhps1 --control-mode right      # 或 both

# 终端 2：实验条件控制台
./run_rhps1_experiment_console                     # 输入 1-4 切换，s 状态，q 退出
```

- 每次切换都会生成新 session，机器人保持不动，操作者按 menu 后才继续跟随。
- 控制台显示 `✓ controller 已切换` 才算生效；3 s 内没有确认会提示检查 controller / 网络。
- 每次发送与确认都记录在 `~/.local/share/rhps1_cornel_vive_controller/experiment_sessions.csv`。
- 组间复位：RViz `Avatar / Experiment Reset` → `Reset to experiment start pose`（8 s 平滑回到起始姿态）。
- 共享自主状态：RViz `Avatar / Shared Autonomy / <左右手>` 的 `Status`。有辅助的条件下若显示 `WAITING`，
  说明没有意图数据，此时实际是纯手动，不能当作“有辅助”试次。
- 旧的 `./run_rhps1_experiment N` 仍可用，但每次切换都会重启 talker，不再推荐。

## 9. 可选：ZED 画面（Vision PC）

在 Vision PC 运行 `zed_stream`（从 Terminal PC 用快捷命令 `v` 登录）。Operator PC 上预览：

```bash
cd ~/luyisi/rhps1_cornel_vive_controller/operator_pc
source /opt/ros/humble/setup.bash
export ROS_DOMAIN_ID=201
export RMW_IMPLEMENTATION=rmw_fastrtps_cpp
export ROS_LOCALHOST_ONLY=1
unset ZENOH_SESSION_CONFIG_URI
python3 ./zed_stream_ros2_publisher.py --stream 10.16.236.200:30000 \
  --topic /rtgr/local/zed/left/image_raw --fps 20 --preview
```

图像链特意使用独立的 domain 201，与 VIVE 控制链（domain 200）隔离。

已确认（2026-11-24）：头部相机为 **ZED Mini**（S/N 18435292，1920x1080@15fps，基线 6.3 cm），
本机 RTX 4070 可从视频流直接算深度（NEURAL，有效像素 99%）。头部平视时**看不到桌面和机器人的手**。

**单一 ZED 接收进程**（Codex 9-30 设计，11-24 并入）：`./run_zed_sdk_ros_bridge_local` 同时发布 HMD 用 JPEG
和意图识别用的 RGB / 深度 / camera_info（`/rtgr/robot/head_camera/...`，frame `head_camera_optical_frame`），
走本机 domain 201 + CycloneDDS，不经过 VIVE 控制网络。**同一时间只能有一个进程读 ZED 流**，否则会丢帧、冻结。
意图识别（发布到 domain 200 的 `/goal_beliefs`）接入这些本地话题还需要跨 domain 方案，尚未搭建。

**帧率（11-24 用本机 USB ZED Mini 测）**：头显 JPEG 约 14.5 Hz（满帧），RGB / 深度 / camera_info 10 Hz
（`RHPS1_ZED_DEPTH_FPS`，默认 10，0 = 每帧；降低可省 GPU）。改之前分别为 10 / 6 / 4 Hz：
接收进程的限帧判断会丢掉提前一点到达的帧；约 1 MB 的图像超过系统默认 208 kB 的 socket 接收缓冲而丢包。
**本机需要一次性设置**（只提高上限，不影响 VIVE/Zenoh）：
```bash
sudo sysctl -w net.core.rmem_max=33554432                                         # 立即生效，重启后失效
echo 'net.core.rmem_max=33554432' | sudo tee /etc/sysctl.d/60-rhps1-cyclonedds.conf  # 永久
```
订阅这些话题的程序需设置 `CYCLONEDDS_URI=file://<operator_pc>/config/cyclonedds_local_images.xml`
（两个启动脚本已自动设置；没调系统上限时自动退回默认缓冲，不会启动失败）。
没有 Vision PC 时可用本机 USB ZED 代替：`python3 operator_pc/tools/zed_local_stream_sender.py`，
再 `RHPS1_ZED_STREAM_ENDPOINT=127.0.0.1:30000 ./run_zed_sdk_ros_bridge_local`（ZED 需接 USB 3 口）。

**HMD 中显示头部画面**：`./run_zed_vulkan_hmd_overlay`（Vulkan 纹理 overlay，不会让 SteamVR 崩溃；默认自己启动
单一接收进程且不算深度）。若 `run_zed_sdk_ros_bridge_local` 已在运行，用 `RHPS1_OVERLAY_SUBSCRIBE_ONLY=1 ./run_zed_vulkan_hmd_overlay`。
11-24 现场记录为**大部分时间白屏**，之后用户反馈已能在 HMD 中看到 ZED 画面（稳定性待下次确认）；不要再用 `run_zed_sdk_hmd_overlay_local`
（会让 SteamVR compositor 几秒内崩溃）。原因与后续修复见 `operator_pc/hmd_vulkan_overlay/README.md`。

**录下 HMD 里的画面**：`./run_record_hmd_view`（存到 `~/rhps1_hmd_recordings/hmd_view_<时间>.mp4`；终端里 `s`+回车截图，
`q`+回车停止）。录的是 HMD overlay 显示的同一个 JPEG 话题，只订阅、不影响 HMD 和意图识别。SteamVR 的“显示 VR 视图”在本机
全白（Intel 核显 Mesa 23.2 不支持 dmabuf 修饰符，日志 `Supports dmabuf formats + modifiers? - No!`），不修。
**白屏原因（11-27 日志核对）**：HMD 闲置待机（SteamVR“在此之后关闭显示”默认 5 秒，已改 5 分钟），不是 overlay 程序问题。
备用方案（HMD+SteamVR+VIVE 搬到 Terminal PC）见 `terminal_pc/README.md`。

## 10. 常见故障速查

| 现象 | 优先怀疑 |
|---|---|
| `bodystat` 无法启动 | 共享内存未建立 → `RHPS1init` |
| CORBA naming service 异常 | 负责人确认后运行 `clear-omninames.sh` |
| OmniORB 地址错误 | `/etc/omniORB.cfg` 的 host 与 nocnoid 的 host 不一致 |
| `nocnoid22.py` 找不到 RTCManager | `hrpsys_mc_rtc.sh` 没有正常启动，与 VIVE 无关 |
| `bodystat` 停止刷新，绿灯长亮，腿部红灯亮 | IOB/EtherCAT/硬件冻结，只能现场重启，**不要继续发运动命令** |
| `vr_interface_msgs ... invalid` | 没有 source workspace，或没用 `sudo -E` |
| RViz 中 Vive 状态不刷新 | 以 `ros2 topic echo --once` 的结果为准 |
| 控制有延迟 | 确认是 Release 构建，且 run loop 里没有阻塞操作 |
