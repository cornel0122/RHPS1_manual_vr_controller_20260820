# RHPS1 迁移修改记录

## 目标

在保留当前稳定 HRP4CR 系统的前提下，为以下链路增加 RHPS1 支持：

```text
Valve Index / Vive tracker
  -> ViveSimpleInterface ROS 2
  -> ANA Avatar Controller
  -> RHPS1_sake2_sake2_MuJoCo
  -> 机器人头部相机 / HMD overlay
  -> Guillaume 或 Cornel 意图识别
  -> Guillaume SharedAutonomy
```

## 迁移前状态

- HRP4CR 启动器：`run_ana_mujoco`
- 主机器人：`HRP4CRFixed`
- controller 周期：`0.005 s`
- Vive：自然站立 BODY/waist 参考映射
- 线速度前馈：开启
- 角速度前馈：关闭
- 共享自主：默认关闭
- Cornel IntentRecognitionBridge：默认关闭

## 计划修改

- 安装 `rhps1_mj_description-master`
- 新增 RHPS1 独立 MuJoCo 启动器
- 在 ANA YAML 中补充 RHPS1 frame、关节、夹具、碰撞和稳定器配置
- 将 Vive Bridge 中机器人手 frame 和夹具关节改为可按机器人配置
- 为 SharedAutonomy 和 IntentRecognitionBridge 添加 RHPS1 frame/active joints
- 让头部相机使用 RHPS1 的 `ZMiniCenter`
- RHPS1 初期关闭 MuJoCo adhesion，保留正常夹具

# 2026-07-29 RHPS1 浮动基座初始化修复

## 现象

- MuJoCo 窗口刚出现时，RHPS1 不在地面上的正常初始高度。
- 随后机器人整体被猛烈弹起并跌落。

## 根因

RHPS1 的三个 MuJoCo XML 都把浮动根关节写成了没有名称的
`<joint type="free"/>`。`mc_mujoco` 依靠根关节名称查找其 `qpos`
索引；没有名称时不会调用 `setPosW` 写入 RobotModule 提供的
`z=0.837656 m` 初始根位姿。结果是物理模型从 `z=0` 开始，双腿
深埋地面，并被接触求解器弹飞。

## 修改

以下文件的浮动根关节统一命名为 `Root`：

- `guillaume_code/rhps1_mj_description-master/xml/RHPS1_sake2_sake2.xml`
- `guillaume_code/rhps1_mj_description-master/xml/RHPS1_leap_leap.xml`
- `guillaume_code/rhps1_mj_description-master/xml/RHPS1main.xml`

此前用于诊断的碰撞排除和 `z=0.8365 m` 高度试验均已撤销，没有
保留在运行配置中。

## 验证

- ANA 启动后的初始阶段：实际浮动基座从 `z=0.8376 m` 开始，在
  约两秒内稳定到 `z=0.8361 m`，不再从地下弹起。
- `run_rhps1_mujoco_model`：约 44 秒仿真时间内，根高度保持在
  `0.8353–0.8376 m`，最终为 `z=0.83606 m`，模型稳定站立。
- ANA 的 `PutHandsAboveTable` 自动动作仍可能使 RHPS1 后续失衡；
  这是控制器迁移问题，与本次基础坐标修复无关，后续单独处理。

# 2026-07-29 RHPS1 启动抬手失稳修复

## 诊断结论

- `Pause` 阶段基座稳定，浮动基座约为 `[x, y, z] = [-0.0005, 0, 0.8361] m`。
- 原配置在仿真时间 `t=2.0 s` 进入 `ANA::PutHandsAboveTable`。
- 抬手过程中 RHPS1 基座持续向后移动并下降；约 `t=5.0 s` 时已经倒地。
- 手部任务能够跟踪原有目标，因此问题不是任务未执行，而是该轨迹只针对
  HRP4CR 的质量分布、手臂结构和稳定器设计，不适合 RHPS1。
- 跳过该轨迹并直接进入 `ANA::Retargetting` 后，约 28 秒仿真时间内：
  - `x` 保持在 `[-0.0009, 0.0002] m`
  - `y` 保持在 `[-0.0000, 0.0001] m`
  - `z` 保持在 `[0.8353, 0.8376] m`

因此，倒地不是桌面碰撞，也不是浮动基座初始位置错误，而是
`PutHandsAboveTable` 对 RHPS1 不适用。

## 永久修复

新增 `RobotVariantDispatch` FSM 状态，在启动时按当前机器人名称选择路径：

- `rhps1`：跳过 `ANA::PutHandsAboveTable`，直接进入 `ANA::Retargetting`
- 其他机器人（包括 `hrp4cr`）：继续执行原始自动抬手流程

涉及文件：

- `guillaume_code/mc_ana_avatar_controller_li_basic/src/states/RobotVariantDispatch.h`
- `guillaume_code/mc_ana_avatar_controller_li_basic/src/states/RobotVariantDispatch.cpp`
- `guillaume_code/mc_ana_avatar_controller_li_basic/src/states/CMakeLists.txt`
- `guillaume_code/mc_ana_avatar_controller_li_basic/etc/ANAAvatarController.in.yaml`

## 回归验证

- RHPS1 实际状态路径：
  `Pause -> ANA::InitialPoseDispatch(Skip) -> ANA::Retargetting`
- RHPS1 在 `Retargetting` 中保持稳定站立。
- HRP4CR 实际状态路径：
  `Pause -> ANA::InitialPoseDispatch(Run) -> ANA::PutHandsAboveTable -> ANA::Retargetting`
- HRP4CR 原始启动动作和后续流程均保留。

## 后续注意

RHPS1 在没有 Vive 输入时，左手力约束会反复报告超过阈值并释放。它没有
导致本次站立失稳，但正式接入 Vive 做手臂遥操作时仍需观察；必要时应为
RHPS1 单独调整手部力约束参数，而不是复用 HRP4CR 的参数。

# 2026-07-31 RHPS1 低刚度慢速划臂试验

## 试验参数

- 保持 HRP4CR 原目标位置和控制点不变。
- RHPS1 专用轨迹刚度由 `500` 降为 `100`。
- 轨迹持续时间由 `5 s` 延长为 `10 s`。
- 试验前备份：
  `backups/rhps1_before_slow_initial_pose_20260731_133010`

## 结果

- `Pause` 结束时基座稳定在 `z=0.8361 m`。
- 慢速轨迹开始后，基座仍持续向后漂移。
- 约 `t=7 s` 开始明显倒地；`t=8 s` 时基座已经降到 `z=0.1813 m`。
- 最终基座约为 `x=-1.0843 m, z=0.1881 m`。
- 与原参数相比，降低刚度和速度只延迟了倒地，没有消除失稳。

## 结论

问题不是单纯的动态冲击，而是 HRP4CR 的双手目标姿态及控制点与 RHPS1
的身体结构、质量分布和当前稳定器不兼容。RHPS1 已恢复为跳过该轨迹的
稳定默认路径。若以后需要准备动作，应根据 RHPS1 的当前手位和 CoM/ZMP
重新设计目标，而不能继续沿用 HRP4CR 的绝对目标。
