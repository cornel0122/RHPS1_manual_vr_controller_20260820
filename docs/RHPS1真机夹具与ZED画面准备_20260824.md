# RHPS1 真机夹具与 ZED 画面准备

本文只扩展已经打通的基础手动链路：

```text
Vive -> Operator PC -> Control PC -> ANAAvatarControllerRHPS1_manual -> RHPS1
```

共享自主保持关闭，输入延迟保持 0 秒。

Operator PC 的 Vive 启动入口也已包含在仓库中：

```bash
./operator_pc/run_vive_talker_rhps1
```

## 1. 实体夹具

`ANA::ViveHandBridgeManual` 已明确应用以下安全参数：

```yaml
gripper_safety_enabled: true
gripper_safety:
  threshold: 8
  iter: 8
  release: 0
  vmaxPercent: 0.05
```

含义：夹具以最大关节速度的 5% 闭合；命令位置与编码器位置误差超过 8 度并连续保持
8 个控制周期后，将目标停在当前实际位置。RHPS1 的控制周期为 0.005 秒时，对应约 40 ms。

这属于位置误差安全，不是力控制，不能保证柔软物体完全不变形。首次真机测试必须：

1. 由 RHPS1 工程师确认实体夹具已安装并由 RobotModule 注册为 `l_gripper`、`r_gripper`；
2. 确认主动关节名称为 `L_HAND`、`R_HAND`；
3. 先空载检查开关方向；
4. 再用硬质、低价值测试物体检查接触停止；
5. 最后才测试实验用瓶子。

启动日志应包含类似内容：

```text
left gripper safety: threshold=8.0deg, iter=8, release=0.0deg, vmax=5.0%
right gripper safety: threshold=8.0deg, iter=8, release=0.0deg, vmax=5.0%
```

若 RobotModule 中没有夹具，controller 只打印警告并跳过夹具，不影响手臂遥操作。Vive 按键仍为：

```text
menu   -> 左右手分别确认，双侧确认后开始追踪
grip   -> 对应侧夹具开/关
trigger -> 预留的“已抓住物体”通知
```

## 2. Vision PC 与 ZED

实验室已有流程为：在 Terminal PC 输入 `V` 进入 Vision PC，然后执行：

```bash
zed_stream
```

`V` 是实验室提供的 SSH/登录别名，不属于本仓库。`zed_stream` 很可能启动的是 ZED SDK
网络流，而不是 ROS 2 `sensor_msgs/Image`。因此准备了两种接入方式。

### 2.1 优先检查 ROS 2 图像 topic

在 Operator PC 上运行：

```bash
cd ~/RHPS1_manual_vr_controller_20260820
./operator_pc/inspect_zed_ros2_topics
```

如果能看到真实 ZED 的 `sensor_msgs/msg/Image` topic，直接指定它：

```bash
export RHPS1_ZED_RGB_TOPIC=/实际/ZED/RGB/topic
./operator_pc/run_hmd_zed_overlay_rhps1
```

旧 ANA/HRP4CR 文档曾使用：

```text
/zedm/zed_node/left/image_rect_color
```

但这是 ROS 1 时代的名称，RHPS1 现场必须以 `inspect_zed_ros2_topics` 的实际输出为准。

建议最终把真实图像统一 relay/remap 为：

```text
/rtgr/robot/head_camera/rgb/image_raw
```

这样 overlay、Cornel 感知和以后共享自主可以使用同一入口。

### 2.2 只有 ZED SDK 网络流时

本仓库包含：

```text
operator_pc/zed_stream_ros2_publisher.py
operator_pc/run_zed_sdk_hmd_overlay_local
```

它们在 Operator PC 本地完成：

```text
Vision PC ZED SDK stream
  -> pyzed.sl 接收
  -> 本机 ROS 2 Image
  -> OpenVR overlay
  -> HMD
```

这种方式把图像留在独立的本机 ROS domain 201，不经过 Control PC 的 Zenoh router，避免高带宽
图像影响 Vive 控制消息。运行前 Operator PC 必须安装与 Vision PC 相容的 ZED SDK 和其
`pyzed.sl` Python API。不能用名称相似的普通 PyPI 包代替 Stereolabs ZED SDK Python API。

先在 Vision PC 查询地址和启动流：

```bash
hostname -I
zed_stream
```

然后在 Operator PC 运行，默认端口按 Walid 旧接收程序使用 `30000`：

```bash
cd ~/RHPS1_manual_vr_controller_20260820
export RHPS1_ZED_STREAM_ENDPOINT=<VISION_PC_IP>:30000
./operator_pc/run_zed_sdk_hmd_overlay_local
```

同时在桌面显示同一相机源用于录像：

```bash
export RHPS1_ZED_DESKTOP_PREVIEW=1
export RHPS1_ZED_STREAM_ENDPOINT=<VISION_PC_IP>:30000
./operator_pc/run_zed_sdk_hmd_overlay_local
```

当前开发用 Operator PC 上尚未检测到 `pyzed.sl`，所以该备用链路已经完成语法和接口准备，
但必须在安装 ZED SDK 后才能现场运行验证。

## 3. 推荐现场顺序

1. 保持共享自主关闭、延迟为 0；
2. 单独启动 ZED，确认 Operator PC 能收到稳定画面；
3. 启动 SteamVR 和 overlay，确认 HMD 画面及桌面预览；
4. 不拿物体，验证实体夹具空载开合与方向；
5. 用硬质测试物验证 5% 速度和接触停止；
6. 保持上述链路不变，再部署 Cornel 感知和 Guillaume 辅助状态。

共享自主不应与相机/夹具首次调试同时启用。这样出现问题时，可以明确区分视觉传输、夹具硬件、
手动遥操作和辅助控制四条链路。
